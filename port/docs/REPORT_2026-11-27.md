## The frame where a level appears

The owner's second 0.1.20 session: one 672 ms frame at load-in, in the 5 s window that built 783 pipelines. With the
deferred bind each one was probed on the GPU thread and, being in the driver's cache, created there (~0.86 ms).
#143 sends those to the 6 compiler threads too. What is left of that frame (~235 ms) is the game's own load-in work
and the recording thread waiting for the builds in draw order.

session's pipelines in the background at start (a list of the pipelines each session asked for, 640 of them) did not
shorten it measurably (235/223 vs 234/242 ms): not merged.

## Gotchas

- `lib_ab.sh` reads stdin: in a shell loop it ate the loop's input and the next runs did nothing. Use `< /dev/null`.
- A GPU library build that changes renderer or recompiler sources gets a new cache key: the next start precompiles
  in full (and then counts the driver's cache as warm).
