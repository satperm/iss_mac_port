## shadPS4 #5745 (texture cache image freed twice)

Same structure here (agent's read-only check): `Rasterizer::UnmapMemory` frees images on the calling thread
through `RunForeign`, which runs inline unless `TLG_FOREIGN_SERIALIZE=1`; the GC frees on the GPU thread; both
under the texture cache mutex. The safe path exists but is opt-in.

## Held frames

The owner's second 0.1.19 session held ~18 frames a minute without new pipelines in the log. The Perf line now
splits skipped draws by cause. A scripted Seattle run (`pad/seattle_run.txt`, 170 s, precompiled cache like a
player's) in the second session: nearly all skips were pipelines being built, not shaders.

- With the precompiled cache only shader stages load at start; each pipeline a session meets is built on its
  first draw: 758 builds in 170 s, 1.1 ms median, 2.2 ms p90 (the driver's cache has them). The draw was skipped
  meanwhile, and the frame held. (The log's "new pipeline" warnings do not cover these builds; the Perf line's
  `new_pipes` now does.)
- Building all of the cache's pipelines at start (`TLG_WARMUP_BUILD_CACHED=1`: 19.6k in 7.8 s, +0.9 GB) did not
  remove them: the game also meets variants outside the precompiled set.
- `TLG_GFX_DEFERRED_BIND=1` (existing, never measured): the pipeline is built on a compiler thread and the
  recording thread waits at the bind. Now the default (#115).

| Seattle run, 170 s | default | deferred bind |
|---|---|---|
| held frames, 2nd session (2 runs) | 137, 137 | 1, 1 |
| held frames, 1st session after a precompile | 191 | 74 (shader stages) |
| frame time p99 (median of 5 s windows) | 12.3-12.8 ms | 13.0-13.5 ms |
| worst frames (top 3) | 24-35 ms | 24-44 ms |

Steady scenes, 3 x 60 s: truck 87.7 / 87.2, Seattle 86.4 / 85.2, bridge 111.7 / 114.1 FPS.

**Cold Metal cache (#120).** The app's Metal cache moved aside, startup probe off (the worst case: a partly evicted
cache the probe does not catch), Seattle run:

| | held frames | worst frames |
|---|---|---|
| wait at the bind (#115) | 47 | 0.9, 2.2, **5.1 s** |
| skip (before #115) | 835 | 0.4, 0.6, 1.4 s |

Each wait is then a full compile. A bounded wait (8 ms a draw, 16 ms a frame, skip past it) did worse (held 138 warm,
a 20 s frame cold) and was dropped. Now (#120) the wait is enabled only when the startup probe found the driver's
cache within 4x of its baseline, or a full compilation just ran; otherwise draws are skipped as before. As a player
starts (precompiled cache, probe on): skip_pipe 0, held 64 (shader stages, first session after a precompile).
`TLG_GFX_DEFERRED_BIND=1` forces the wait, `=0` turns it off. The Metal cache was put back afterwards (1.4 GB).

## Detailed benchmark (#116)

A run through ISS.app (`open ISS.app --args --detailed-benchmark`) on this Mac with the FPS cap at 60 took 190 s and
wrote:

```text
Verdict: Frame rate cap (60 FPS held, GPU busy 52%).
Memory: 7.0 of 36 GB, pressure normal, swap 888 MB used
Your settings (1920x1080): 60.0 FPS median, frame time p50 16.7 / p99 16.7 / p99.9 16.7 ms, GPU busy 52%
Half render scale (960x540): 60.0 FPS median, ..., GPU busy 76%
Port threads (% of one core): game_unnamed 91%, VkRecorder 46%, DrawRec 44%, GpuCommandProcessor 44%
```

- The half run halves the size even with a native output resolution (`TLG_BENCH_HALF_SCALE=1`); the agent's first
  version passed `TLG_RENDER_SCALE`, which the game ignores there, and would have called a GPU-bound Mac CPU-bound.
- Uncapped (own launch.conf): "CPU-bound (half render scale +8% FPS; busiest port thread DrawRec 64%)": 91.2 FPS at
  1920x1080, 98.4 at 960x540, GPU busy 73% / 72%. Matches the causal sweep.
- GPU busy is a share of time at the GPU's current clock: at a capped frame rate Apple GPUs clock down, so 76% at
  half size against 52% at full size is not a contradiction. The verdict reads the cap first for that reason.

## Causal sweep (which stage sets the frame)

A fixed busy-wait per draw (stage A, stage B) or per recorded command (the Vulkan recorder), 2 x 60 s:

| +200 ns | Truck 1080p (88.0) | Burning village 4K (30.9) |
|---|---|---|
| Stage A, per draw | 84.2 (-4.3%) | 30.8 (-0.3%) |
| Stage B, per draw | 83.0 (-5.7%) | 30.7 (-0.6%) |
| Vulkan recorder, per command | 64.8 (-26%) | 29.9 (-3.2%) |

The recorder (`tlg:VkRecorder`, MoltenVK's command encoding) is the critical CPU stage, even at 4K. Its cost per
command is what to cut at 1080p: fewer commands (render passes, barriers, push constants that repeat) or cheaper
ones in MoltenVK. Stages A and B have slack.

`TLG_FOREIGN_SERIALIZE=1` (the safe path for #5745's race) costs nothing measurable: truck 88.0 / 88.2, Seattle
85.6 / 85.1 (3 x 60 s). Not made the default today: it changes thread ordering on unmaps (loads), and a guest thread
then waits on the GPU side; that needs load-heavy soaks first. Recommended for the next release candidate.
